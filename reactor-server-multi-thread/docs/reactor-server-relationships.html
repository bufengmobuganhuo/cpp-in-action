Reactor Server 关系与事件路径

这些 Archify 图表基于当前仓库中的 EchoServer、TcpServer、Acceptor、Connection、Channel 和 EventLoop 实现，分别展示类关系、连接建立、消息 echo 回复、空闲超时销毁和服务器停止路径。

类关系与职责 谁持有谁、Channel 如何连接 EventLoop 与业务回调。 客户端连接到来 listen fd 就绪后，从 accept_channel_ 到 Connection 的创建路径。 消息处理与回复 EPOLLIN 读入、业务线程构造回复、EPOLLOUT 写出的完整链路。 空闲超时销毁 timerfd 扫描连接表并移除 shared_ptr 的路径与风险点。 服务器停止 EchoServer::stop 到 EventLoop 唤醒退出、线程池 shutdown 的停止链路。

关键结论

  • Acceptor::accept_channel_ 监听新连接；Connection::client_channel_ 监听客户端读写和断开。
  • EventLoop 不直接理解业务，只从 Epoll 取出 ready Channel 并调用 Channel::handle_event()。
  • TcpServer 是回调桥接层：连接事件来自 Reactor，业务动作转发给 EchoServer。
  • 空闲超时当前通过 erase 两级 conns_ 释放连接，但代码没有在超时路径显式移除 client_channel_ 的 epoll 监听。
  • EchoServer::stop() 先关闭业务线程池，再通过 TcpServer::stop() 停止主从 EventLoop 和 acceptor 线程池。
